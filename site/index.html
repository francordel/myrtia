The console

Configure, watch, measure.

Three views and an assistant. Everything a run produces is persisted, searchable and replayable, and the same vocabulary follows you from the live stream to the dashboard.

Runs

A launcher in four steps

Attack, target, behaviours, council. Advanced settings stay one click away, the launch button never leaves the screen, and the run header tells you what you are looking at: attack, agents, target, date, status and best score.

Live deliberation

Every turn, as it happens

Proposals, Borda ranking, the exact prompt the chairman sent, the target's answer and the judge's rationale stream over WebSocket. Goals collapse as they finish; a goal index keeps long runs navigable.

Behaviour library

278 behaviours, five themes

HarmBench behaviours across chemical and biological, cybercrime, harassment, illegal activity and misinformation, searchable and selectable per theme. Or type your own goals.

Statistics

ASR you can defend

Attack Success Rate by attack, target model and theme, the judge-score distribution, average best score and, for council runs, how often each agent's proposal won the vote.

History

Search, filter, replay

Every run filtered by text, attack, theme, run status and outcome, sortable by date or score. One click reopens the full deliberation.

Assistant

A chat that knows your stats

A built-in assistant, on the provider and model of your choice, that explains attacks, helps configure a run and answers questions about your live numbers.

Attacks

Six strategies, one contract.

Attacks are plugins with an ARES-compatible contract and their own advanced settings in the UI. Council attacks carry an in-loop judge; the self-contained baselines record the raw target response for you to grade.

AttackWhat it doesScoring
councilN attacker models propose, cross-critique and vote (Borda Top-1); a chairman synthesises the winner and strikes the target. Each turn is a fresh standalone prompt.in-loop judge 0-5
council-crescendoThe same council pipeline, but the target conversation accumulates across turns: a gradual multi-turn escalation.in-loop judge 0-5
directSends each behaviour to the target verbatim. The baseline every other attack is compared against.raw response
human-jailbreakWraps each behaviour in known public persona templates (DAN, AIM, dev-mode and others) and sends every variant.raw response
obfuscationEncodes the behaviour (base64, ROT13, leetspeak, reversed) and asks the target to decode and comply. Tests whether safety filtering survives surface transforms.raw response
payload-splittingBreaks the behaviour into innocuous fragments and asks the target to reassemble and act on them, so the harmful string never appears verbatim.raw response

Build your own agentic attack

  • Council models. Any mix of local and hosted models as attacking agents.
  • Council system prompt. The attacker persona and context shared by the agents, or the built-in red-team prompt.
  • Critique style. Hardened or soft cross-critique.
  • Chairman and judge. Separate models for synthesis and grading, with their own endpoint.
  • Turns and voting. Turn budget per behaviour, Borda cross-critique and chairman synthesis on or off.

The realistic threat model

  • Safety-aligned frontier models refuse to author jailbreaks, so they make poor attackers.
  • Myrtia pairs a permissive open-model council (for example local Ollama models) with the frontier target under test.
  • A capable judge is load-bearing: a weak judge inflates ASR. Use the best model you can afford as judge.

Results

Two questions, two answers.

"Did the run finish?" and "did the attack work?" are different questions, so Myrtia never mixes their vocabulary. Green is never used to mean "completed".

Security by default

Built to be run on your own machine.

Myrtia is a local, single-operator tool. It is careful with your keys and with what the backend is allowed to reach.

Keys stay in the browserAPI keys are supplied at run time, stored only in your browser, and redacted from every API response and from the live event stream.
SSRF guardLink-local and cloud-metadata addresses are refused for targets, council calls and the assistant; loopback and LAN endpoints remain available.
Local-only CORS and CSPThe API only answers the local origins you run it on, with a Content Security Policy, frame denial and nosniff headers.
Durable historyRuns, events and statistics persist in a local SQLite database with owner-only permissions and survive restarts.
Stop any runCooperative cancellation ends a running attack at the next turn, from the run header.
Escaped everywhereModel names, themes and rationales from the API are escaped before rendering; external links must be http(s).
Why Myrtia

The multi-agent threat model, made observable.

Library and CLI tools such as IBM ARES and NVIDIA garak are the reference for LLM red teaming. Myrtia keeps their rigour and adds autonomous multi-agent attackers, a real console and analytics.

Quick start

Running in three commands.

Python 3.11+. A local Ollama with a small model is enough to see a council deliberate without any API key.

# install
cd backend && pip install -e . && pip install -e vendor/ares-council

# run the server (API + console)
uvicorn myrtia.api.app:app --port 8000

# open the console
open http://127.0.0.1:8000/
